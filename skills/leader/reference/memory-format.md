## Daily log

Path: `memory/dev/daily/YYYY-MM-DD.md`

```markdown
# YYYY-MM-DD

## Work Done

## Decisions

## Next Actions

<!-- auto-generated:start -->
<!-- Last updated: YYYY-MM-DD HH:MM by dream skill (Phase 5) -->

## Work Done
- ...

## Decisions
- ...

## Next Actions
- ...

## Highlights
- ...

## Open questions
- ...

## Retrospective proposals
- R-N1: ...
<!-- auto-generated:end -->
```

Anything **outside** the `<!-- auto-generated:start --> ... <!-- auto-generated:end -->` markers is handwritten and preserved across dream runs. Anything **inside** is regenerated by dream Phase 5.

## Retrospective

Path: `memory/dev/retrospectives/YYYY-MM-DD.md`

```markdown
# YYYY-MM-DD Retrospective

## Good points

## Improvements

## Process / skill issues

## Proposals
<!-- Each finding from the Retrospective trigger goes here as R-N with a status line. -->

## Action Items
- [ ] ...

## Carry-over (needs confirmation)
```

## Index formats

- `memory/dev/daily/index.md` — `| Date | Summary |` (newest first)
- Tasks/issues — stored in GitHub Issues, query with `gh issue list` (no file index)
- `memory/dev/decisions/index.md` — `| ID | Title | Status | Date |`
- `memory/dev/notes/index.md` — `| Topic | Updated | Summary |`
- `memory/dev/retrospectives/index.md` — `| Date | Summary | Reported | Adoption |` (newest first)

## Auto-generated marker zone (dream Phase 5)

The marker zone `<!-- auto-generated:start --> ... <!-- auto-generated:end -->` in today's daily log is rewritten by the dream skill Phase 5 every time the 24h cache check fires.

- **6 sections** in fixed order: Work Done / Decisions / Next Actions / Highlights / Open questions / Retrospective proposals
- **Trigger**: dream skill 24h cache (dispatched by the leader / consumer on activation)
- **Locale**: dream auto-detects the consumer's primary language from existing content. Japanese consumers see Japanese section headings.
- **Hand-edits**: any text **outside** the markers is preserved across runs. Add handwritten notes **above** `<!-- auto-generated:start -->`.

If the daily file does not exist when dream runs, dream creates just the header (no marker zone) in dry-run, or header + empty marker zone in apply mode.
